# Path dependence extension (handoff 1)

Same 1,000 examples (250 `bad_medical` + 750 `evil_numbers`), same
hyperparameters and step count, different **order**.

## Run it

Open `15_path_dependence_colab.ipynb` in Colab on an A100/L4 runtime and run
all cells. It keeps everything on Google Drive and skips finished work, so it
can be re-run after a disconnect.

By hand:

```bash
python 13_make_ordered_mixture.py                       # + --verify to re-check
for o in random harmful_first harmful_last; do
  python 09_finetune_dataset.py \
      --dataset-jsonl artifacts/ordered_mixture_seed42/mixture_${o}_seed42.jsonl \
      --sequential --save-every 5 --run-name mixture_${o}_seed42
  python 10_measure_dataset_drift.py --run-name mixture_${o}_seed42
done
python 14_ordering_analysis.py
```

## Files

| file | role |
|---|---|
| `13_make_ordered_mixture.py` | picks the multiset once, writes each order, manifest with per-example hashes; `--verify` re-proves identity |
| `09_finetune_dataset.py` | + `--dataset-jsonl`, `--sequential`, `--save-every`, `--model-name` (smoke tests only); logs example IDs per optimizer step to `step_example_ids.jsonl`. Without the new flags it behaves exactly as before. |
| `14_ordering_analysis.py` | verifies the logged order, metrics table, figures |
| `15_path_dependence_colab.ipynb` | end-to-end Colab pipeline (generated by `build_colab_notebook.py`) |

## Design decisions

- **Selection reuses the reproduction's sampling.** The 250 harmful / 750
  benign examples are the first 250 / 750 of the exact 1,000-example samples
  the pure `bad_medical` / `evil_numbers` runs trained on.
- **Every condition uses `--sequential`**, including `random` (a pre-shuffled
  file). The original trainer shuffles with `DataLoader(shuffle=True)`, which
  would erase the ordering manipulation.
- **Order repeats in epoch 2.** With 2 epochs, `harmful_first` is
  H → B → H → B and `harmful_last` is B → H → B → H. The protocol (2 epochs,
  126 steps) is kept as-is; the per-step harmful-share strips in
  `trajectory_pc1.png` show this explicitly.
- **Within-group order is held fixed** across `harmful_first`,
  `harmful_last` and `alternating_blocks` (5 × [B75 H50 B75]).
- **Identical seeds** mean LoRA initialisation and dropout draws are the same
  across conditions; the data order is the only difference.
- **Fixed instrument.** Runs are projected onto the saved
  `qwen_seed42_pc1.json`; PC1 is not refit on the new runs. PC2 is recomputed
  from the same four calibration endpoints as `11_pc1_fit.py` (checked to
  reproduce the saved PC1). Projection matches `12_plot.py`.
- **Checkpoints every 5 steps** (vs 10) because the harmful block lasts only
  ~16 optimizer steps. Saving more often does not change training.
- **Threshold** for "time above threshold" defaults to the pure
  `evil_numbers` final |PC1| (12.84%).

## Caveats

One seed. PC1 drift is a representation measure, not behavioral EM.
